# sentinel (core library)

Namespace `com.infinum.sentinel`. Sources are in `src/main/kotlin/com/infinum/sentinel/`. There is no Compose and no Java.

## Public API

Everything else is `internal`.

- `Sentinel.kt`:
  - `Sentinel.watch(tools, targetedPreferences)`, `show()`, `setExceptionHandler(...)` and `setAnrListener(...)`
  - the `Sentinel.Tool` interface and its typed sub-interfaces (`NetworkTool`, `MemoryTool`, `AnalyticsTool`, `DatabaseTool`, `ReportTool`, `BluetoothTool`, `DistributionTool`, `DesignTool`), which supply a default `name()` string
  - `ApplicationNotRespondingListener` and `ApplicationNotRespondingException`
- `SentinelInitializer.kt`: an `androidx.startup` initializer declared in the manifest. It calls `LibraryComponents.initialize(context)`.
- `ui/tools/CertificateTool.kt`: the only public built-in tool.
- `res/values/public.xml`: exposes only `sentinel_name` and `sentinel_infinum_monitored`.

Any change here must be mirrored in `sentinel-no-op` (see [../sentinel-no-op/AGENTS.md](../sentinel-no-op/AGENTS.md)). Then run `./gradlew apiDump` and commit `api/sentinel.api`.

## Architecture

- **DI**: kotlin-inject (`me.tatarka.inject`, generated by KSP), not Hilt or Koin.
  - `di/LibraryComponents.kt` holds the component chain `DataComponent` → `DomainComponent` → `ViewModelComponent` → `PresentationComponent` (in `di/component/`, with scopes in `di/scope/`).
  - `DEFAULT_TOOLS` (`CrashMonitorTool`, `BundleMonitorTool`, `AppInfoTool`) are always added to the user's tools.
- **UI**: XML Views with ViewBinding, Activities and Fragments.
  - Base classes are in `ui/shared/base/`. `BaseViewModel<State, Event>` exposes `StateFlow` and `SharedFlow`.
  - Screens live in `ui/main/{application,device,permissions,preferences,tools}`, `ui/settings`, `ui/crash`, `ui/bundles` and `ui/certificates`. Each screen has a Fragment, a ViewModel and a State, and sometimes an Event.
- **Domain**: `domain/` holds repositories and factories (`Repositories.kt`, `Factories.kt`) per feature: collectors, formatters, triggers, formats, preference, crash, bundle and certificate.
  - The crash and ANR monitors are in `domain/crash/monitor`.
- **Data**: `data/`.
  - Room `SentinelDatabase`, with `exportSchema = false` and no migrations. **Bump `DATABASE_VERSION` in `di/LibraryComponents.kt` whenever an entity or DAO changes.**
  - In-memory caches are in `data/sources/memory`.
  - `data/sources/raw/collectors`: one collector per screen section.
  - `data/sources/raw/formatters`: Plain, Markdown, JSON, XML and HTML.
  - Triggers are in `data/models/memory/triggers/`: shake, proximity, foreground, usb, airplanemode and manual.
    - Their defaults can be overridden through manifest meta-data `com.infinum.sentinel.trigger.*`, which `extensions/Context.kt` reads.
    - The manual trigger cannot be disabled.

## Rules

- Every Sentinel activity in `AndroidManifest.xml` must carry `<meta-data android:name="@string/sentinel_infinum_monitored" android:value="false"/>` so that the Bundle Monitor skips it. Use the `Sentinel.Theme.Leaf` theme for child screens.
- `resourcePrefix = "sentinel_"`: prefix every new resource.
- A new public class that is reached by reflection or serialization may need a keep rule in `proguard-rules.txt` (release is minified).

## Tests

- Unit tests (JUnit4) are in `src/test/kotlin`: `./gradlew :sentinel:testDebugUnitTest`.
- Instrumented tests are in `src/androidTest/kotlin` and need a device: `./gradlew :sentinel:connectedDebugAndroidTest`.
  - **Failures are ignored** by the build (`ignoreFailures = true`), so read the report.
- Formatter tests compare their output against golden files `src/androidTest/resources/expected_*.{txt,md,json,xml,html}`, each with a `_no_preferences` variant. If you change collected fields or formatter output, update all formats and both variants.
- Coverage: `./gradlew :sentinel:jacocoTestReport` (configured in `jacoco.gradle`).
